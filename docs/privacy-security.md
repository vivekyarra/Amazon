# Privacy and security

## Design boundaries

These are deliberate product decisions, enforced in code and tests:

- **A human approves every report.** Muni never files police reports autonomously. An owner approves the exact evidence manifest and destination through separate confirmations; an MCP boolean cannot authorize dispatch, and `dispatch_police_evidence_dossier` always denies with an audited event. The demo receiver records the packet but sends nothing.
- **Evidence, not inference, completes a contract.** Motion notifications, unseen objects and model speech extraction cannot mark a physical contract verified. User confirmations retain `USER_CONFIRMED` provenance.
- **No identification or accusation.** There is no biometric or face identification and no automatic accusation. Hashes and the SHA-pinned model establish processing provenance, not medical accuracy or person identity.
- **No hidden capture.** No browser captures audio or video in the background. Camera processing requires consent and stops on revocation.
- **The entertainment gate is voluntary.** Reality-Lock gates Muni's own in-app entertainment; it does not lock third-party apps.
- **Secrets stay on the server.** Browser and TV clients never receive Bee, Ring or AWS credentials, SDP or upstream session URLs. Every contract, incident, media, TV session and event read is household-scoped.

## Authentication and request handling

Authentication uses private bootstrap credentials, memory-only salted scrypt hashes and random 256-bit session tokens. Only SHA-256 token hashes are persisted; sessions expire after eight hours and logout revokes them. Cookies are HttpOnly, SameSite Strict and always Secure in live mode. Live API/MCP access requires HTTPS, configured origins, a provisioned 32-byte owner-only key and owner passwords of at least sixteen characters; the demo administrator is not available in live mode. Replay mutation routes require the isolated demo administrator. Utterances supplied through MCP are labelled as MCP input, distinct from Bee capture.

Writes require strict request validation and idempotency; conflicting reuse returns 409. Origin checks, request bounds, login/command rate limits, CSP, no-referrer, no-sniff and no-store are enforced. The application limiter is per-process, so the reverse proxy also enforces connection, body and time limits. On AWS, backend ingress is limited to the HTTPS front end, and forwarded HTTPS headers are trusted only inside that boundary.

## Encryption

AES-256-GCM encrypts household aggregates, command responses, inbox payloads and artifacts; associated data binds each record to its identity and household. A missing or wrong key, or damaged ciphertext, fails closed. Keys and bootstrap files have owner-only permissions and are git-ignored. Local development keeps the generated key on the private deployment volume; live deployments provision it separately (Secrets Manager on AWS). Plaintext ledgers from older builds migrate only with explicit opt-in (`ALLOW_LEGACY_LEDGER_MIGRATION=true`); never use that flag to work around a missing key for an encrypted ledger.

## Consent and retention

Consent is required before compilation or evidence processing. Revocation cancels queued inbox work, pauses watchdogs and workouts, and stops live camera sessions. Frame callbacks recheck consent transactionally, and the media route refuses revoked access immediately.

Artifacts expire after seven days by default (owner-configurable, below). The worker physically removes expired local bytes and keeps hash-chain tombstones, so retrieval and export distinguish expiration from tampering. Cloud replication keeps ciphertext and adds private SSE-KMS encryption. Retries do not refresh artifact age; the cloud worker deletes every S3 version of expired media and restore never resurrects it. The S3 seven-day lifecycle rule is an additional backstop. AWS PITR, retained volumes and operational backups follow their own retention; transcript and audit metadata are retained until the household is deleted.

## Owner privacy controls

Implemented in `apps/mcp-orchestrator/done_irl/privacy.py`, with routes under `/api/privacy` and a panel on the console's Connections & privacy page. Every write requires an authenticated session for the caller's own household (`owner`, or the judge administrator for the isolated `demo` household only), an `Idempotency-Key` and strict validation, returns a `trace_id`, and emits a `privacy.*` audit event into the encrypted ledger. Settings live inside the household's AES-GCM aggregate, so no other household can read or change them.

- **Per-camera exclusion** (`POST /api/privacy/cameras/exclusion`). Only cameras bound to the caller's household (or `synthetic-porch` in replay) can be configured. An excluded camera cannot start a WHEP session (`CAMERA_EXCLUDED`, checked inside the idempotent command before any external call, including via MCP); an open session for that device stops immediately; frame callbacks recheck exclusion transactionally; signed Ring webhooks from the device are acknowledged with `202 {"processed": false}` without storing the payload; queued inbox events are cancelled and their payload discarded; replay porch scenarios refuse observation and evidence collection.
- **Privacy masks** (`POST /api/privacy/cameras/masks`). Up to 16 normalized polygons (3–64 points in [0, 1]) per camera with an incrementing `calibration_revision` and optimistic revision checks. Masked pixels are zeroed before detection, before the relayed JPEG and frame hashes, and in stored derived evidence (snapshots, person crops, annotated clips) before encoding, so `sha256_original` covers the masked bytes. Each such record carries a `privacy_mask` entry (camera, calibration revision, region count, scope). The replay source clip (`REMOVAL_CLIP_ORIGINAL`) is preserved unmasked and encrypted as the chain-of-custody original, and its manifest entry says so (`ORIGINAL_UNMASKED_ENCRYPTED`). Live Ring video is processed frame by frame and not stored as a clip. Masks complement, not replace, a camera's own privacy zones.
- **Retention** (`POST /api/privacy/retention`, 1–30 days). New artifacts record `retention_days_at_capture`. Existing unexpired artifacts get a new effective `retention_expires_at` from their capture time; the at-capture value moves to `retention_expires_at_original`, which the hash-chain verifier uses, so the chain is never rewritten. Shortening retention deletes now-due bytes in the same transaction and keeps tombstones; expired artifacts are never resurrected. The cloud worker then deletes all S3 versions using the effective expiry.
- **Provider disconnect** (`POST /api/privacy/providers/{bee|ring}/disconnect`). Records a durable `REVOKED` state, deletes the provider cursor, cancels and erases queued inbox payloads, stops the Ring session or Bee stream and drops the in-process Bee token. Integration status shows `NOT_CONNECTED`. Revocation is enforced at enqueue, processing, webhook, camera start and frame callback; toggling consent or restarting never reconnects. Only an explicit owner `.../reauthorize` clears it (Bee streaming then resumes on service restart with provisioned credentials). Provider credentials are server-provisioned secrets, never stored in the ledger; to revoke them upstream, rotate or remove them at the provider and in the secret store.
- **Household deletion** (`POST /api/privacy/household/delete`) requires `household_id` equal to the caller's own household and the exact phrase `DELETE ALL HOUSEHOLD DATA`. In one transaction it deletes that household's contracts, events, alerts, incidents, sub-agents, schedules, evidence bytes and tombstones, inbox receipts, provider cursors, cached command responses and pending cloud outbox snapshots, then disables consent, stops the camera session and checkpoints the WAL. Other households are untouched. A minimal receipt (ID, timestamp, per-type counts, cloud status) and non-content safety settings (camera exclusions, provider revocations, retention days) are kept so deletion never re-enables collection; masks are deleted. With AWS enabled, a `cloud_deletions` job erases every S3 object version under `<household>/`, every DynamoDB item under `HOUSE#<household>` and the household's EventBridge schedules before any newer snapshot is republished; a failure blocks the republish and retries. Operator EBS/SQLite backups, DynamoDB PITR history, CloudWatch logs and provider-held data follow their own retention.

Tests: `apps/mcp-orchestrator/tests/test_privacy.py` (`test_privacy_controls_require_authenticated_owner_and_idempotency`, `test_camera_exclusion_blocks_synthetic_collection_and_is_audited`, `test_live_excluded_camera_cannot_start_and_webhook_is_acknowledged_not_processed`, `test_frame_callback_refuses_excluded_camera_without_evidence`, `test_apply_masks_zeroes_exact_normalized_region`, `test_private_masks_zero_pixels_in_derived_evidence_before_hashing`, `test_retention_setting_updates_existing_and_new_artifacts_without_breaking_chain`, `test_shortened_retention_deletes_due_bytes_immediately_and_never_resurrects`, `test_provider_disconnect_cancels_work_and_never_auto_reconnects`, `test_household_deletion_requires_confirmation_and_is_household_scoped`) and Moto-backed AWS tests in `apps/mcp-orchestrator/tests/test_aws_runtime.py` (`test_household_deletion_erases_only_that_households_cloud_objects`, `test_failed_cloud_erase_blocks_republish_and_retries`).

## Provider integrations

Ring webhooks verify the documented raw-body HMAC signature before parsing and enforce server-side account/device bindings. Durable receipt IDs accept legitimate delayed retries without duplicate processing. The WHEP receiver validates upstream session hosts, video capability and bounded session duration; decoder or model failures pause proof, and only server-derived frames can drive pose completion.

Bee utterances without wearer attribution are held as `NEEDS_CONFIRMATION` rather than treated as the owner's promise.

## Test coverage

Security and negative tests cover cross-household media, forged webhooks, account/device scope, encryption context, evidence tampering, missing keys, expired evidence, consent, retries, stale revisions, count setters, repeated video/pose frames and storage failure.

Sample data contains no private household conversations, addresses or identities. Third-party footage is used under its license and labelled as recorded stock, never as household footage ([references](public-references.md)).
