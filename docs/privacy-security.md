# Privacy and security

Synthetic fixtures contain no private household conversations, addresses or identities. The optional public video reference is licensed/attributed separately and never labeled consented household footage. Browser clients never receive Bee, Ring or AWS credentials. Every contract, incident, media, TV session and event read is household-scoped.

Authentication uses private bootstrap credentials, memory-only salted scrypt hashes and random 256-bit session tokens. Only SHA-256 token hashes are persisted; sessions expire after eight hours and logout revokes them. Cookies are HttpOnly/SameSite Strict and always Secure in live mode. Live API/MCP access requires HTTPS, configured origins, a provisioned 32-byte owner-only key and owner passwords of at least sixteen characters; a demo administrator is prohibited. Replay mutation routes require the isolated demo administrator. MCP owner-provided utterances remain explicitly labeled as MCP input rather than genuine Bee capture.

Writes require strict request validation and idempotency; conflicting reuse returns 409. Origins, request bounds, login/command rate limits, CSP, no-referrer, no-sniff and no-store are enforced. The application limiter is single-process; a reverse proxy must also enforce connection/body/time limits. AWS backend ingress is limited to the HTTPS ALB, so its forwarded HTTPS headers are trusted only inside that network boundary.

AES-256-GCM encrypts household aggregates, command responses, inbox payloads and artifacts; associated data binds each record to its identity and household. A missing/wrong key or damaged ciphertext fails closed. Keys and bootstrap files have owner-only permissions and remain ignored by git. The local generated key shares a private deployment volume for development; live deployments provision it separately. Existing plaintext ledgers require explicit migration opt-in (`ALLOW_LEGACY_LEDGER_MIGRATION=true`) and disposal of old unencrypted backups. Never opt into migration to bypass a missing key for an encrypted ledger.

Consent is required before compilation/evidence processing. Revocation cancels queued inbox work, pauses watchdogs/workouts and stops live camera sessions. Frame callbacks recheck consent transactionally; the media route immediately refuses revoked access. No browser captures hidden audio/video. There is no biometric identification or automatic accusation. User confirmations retain `USER_CONFIRMED` provenance. Motion notifications, unseen objects and model speech extraction cannot mark a physical contract verified.

Artifacts expire after seven days by default. The worker physically removes expired local bytes and retains hash-chain tombstones. Retrieval/export distinguishes expiration from tampering. Cloud replication preserves ciphertext and adds private SSE-KMS encryption. Immutable retries do not refresh artifact age; the cloud worker deletes all S3 versions of expired media and restore never resurrects them. S3 seven-day lifecycle rules are an eventual backstop, not instantaneous deletion. AWS PITR/retained volumes and operational backups have their own retention policies; transcript/audit metadata is not automatically erased after seven days. Household deletion requests, per-camera exclusions, adjustable retention and provider disconnect workflows are **not yet implemented**; their absence remains a full-product release gap.

Ring webhooks verify documented raw-body HMAC signatures before parsing and enforce server-side account/device bindings. Durable receipt IDs accept legitimate delayed retries without processing duplicates. A signed motion notification is not visual evidence. The WHEP receiver validates upstream session hosts, video capability and bounded session duration; decoder/model failures pause proof. Only authorized server-derived frames can drive live pose completion. The SHA-pinned model and per-rep frame hashes establish processing provenance, not medical accuracy or person identity.

Reports end at a private export or isolated synthetic receiver. Exact manifest, destination and deliberate owner confirmation are required for the demo dispatch. An MCP boolean cannot authorize official dispatch. No official police adapter, unsupported native haptic delivery or cross-app TV locking capability is claimed.

Security/negative tests cover cross-household media, forged webhooks, account/device scope, authenticated encryption context, evidence tampering, missing keys, expired evidence, consent, retries, stale revisions, count setters, repeated video/pose frames and storage failure. These are implementation tests; independent security review and production certification remain outstanding.
